確認の前提: この開発環境からは moomoo 公式ドキュメント (openapi.moomoo.com) にアクセスできなかったため、
OpenD の関数名・引数は **PyPI 公開の公式 SDK `moomoo-api` 10.11 のソースコード** で確認した。
実機 (OpenD + moomoo証券(日本) の口座) では一度も動かしていない。

## 1. moomoo 日本口座での API 制限

| 項目 | 内容 | 現在の扱い |
|---|---|---|
| 米国株の模擬口座 | SDK 上は `TrdMarket.US` × `TrdEnv.SIMULATE` が有効 (`MKT_ENV_ENABLE_MAP`)。moomoo証券(日本) の口座 (`SecurityFirm.FUTUJP`) で同じく使えるか | フェーズ 3 で最初に実機確認する |
| 逆指値 (STOP) 注文 | SDK に `OrderType.STOP` (aux_price = 発動価格) と `TimeInForce.GTC` がある。日本口座の米国株・模擬口座で受け付けられるか、GTC が使えるか | フェーズ 3 で確認。使えなければ「建玉に必ず証券会社側の逆指値」を満たせないので**本番には進まない** |
| 逆指値の訂正 | `modify_order(ModifyOrderOp.NORMAL, order_id, qty, price, aux_price=...)` で発動価格を変えられるか | 同上 |
| 寄り付き前の成行予約 | 日本時間の朝に「翌寄り付きの成行」を予約できるか (`OrderType.MARKET`、`TimeInForce.DAY`、時間外の受付可否) | フェーズ 3 で確認。不可なら寄り付き直後に発注する方式に変更 |
| API の頻度制限 | 発注・訂正・照会の回数制限 (公式ドキュメントの「Authorities and Quota」) | 日次 1 回の運用なので数回 / 日。上限に近づかない |

## 3. 決算日データの取得元

| 項目 | 内容 | 現在の扱い |
|---|---|---|
| 次回決算日 (週次スクリーナー) | Yahoo Finance (`yfinance` の `get_earnings_dates`)。非公式 API なので仕様変更・欠損の可能性 | 取れない銘柄はログに「要確認」と出し、`earnings_unknown_policy: exclude` で**除外** (安全側) |
| 過去の決算日 (バックテスト) | 同じく Yahoo (過去 約 15 年分を `limit=60` で取得)。欠けている四半期があり得る | 前回決算から 150 日以上 / 次回まで 120 日以上空いていたら「不明」とみなし除外 |
| moomoo の過去決算日 | `get_financials_earnings_price_history(code)` に `pub_trading_day` 列がある (SDK ソース)。どこまで遡れるか不明 | 未使用 |
| 決算の発表時刻 (寄り前 / 引け後) | 戦略は「決算日の 2 営業日前に手仕舞い」なので、どちらでも間に合う | 対応不要 |

## 5. 現金口座での発注制限

| 項目 | 内容 | 現在の扱い |
|---|---|---|
| T+1 受渡 | 売却代金は翌営業日から再利用できる (ユーザー指定の前提) | バックテスト・資金管理に組み込み済み (`SettlementLedger`) |
| 同日の回転売買 | 未受渡の代金での買付、買った株をその日に売る場合の制限 (日本の証券会社の「差金決済」ルールが米国株にも適用されるか) | 戦略は寄り付きで買い、早くて同日の逆指値で売る。逆指値が同日に約定するケースが規則上問題ないか**要確認** |
| 為替 | 「円から都度両替」の具体的な流れ (円貨決済 / 外貨決済) と、売却後のドルの扱い | 両替コスト 0 と仮定 (`account.fx_cost_pct` で変更可)。為替レートは固定 |
| 買付余力 | `accinfo_query` の `power` / `usd_net_cash_power` (SDK ソースの列名) が日本口座の現金口座で何を表すか | フェーズ 3 で実機確認。自前の受渡計算と小さい方を使う予定 |
| PDT ルール | 米国の Pattern Day Trader 規制は米国の証券会社の信用口座向け。日本の証券会社の現金口座への適用は | スイング (平均保有 数日〜数週間) なので影響は小さい見込み。要確認 |

## 6. データ・バックテストの限界 (確認しても解消しないもの)

- **生存者バイアス**: 銘柄リストは「今上場している普通株」。上場廃止・買収された銘柄が入らないので、成績は良く出る方向に偏る。
  無料で過去時点の上場銘柄リストを得る方法は見つけられていない。
- **過去の時価総額**: 無料で取れないため「現在の発行済株数 × 過去の株価」で近似。増資・自社株買いの影響は反映されない。
- **調整後価格**: Yahoo の分割・配当調整済み価格を使うため、過去の「株価 10〜100 ドル」の判定は当時の実際の株価と少しずれる。
- **臨時休場**: 祝日はルールで計算しているが、国葬などの臨時休場は `swing/calendar_us.py` の `EXTRA_CLOSURES` に手で追加が必要
  (バックテストは SPY の実際の営業日を使うので影響なし。ライブの営業日計算にだけ影響)。
